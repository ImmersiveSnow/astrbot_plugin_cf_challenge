# CF 群聊解题挑战

这是一个 AstrBot 插件，按指定条件从 Codeforces 抽题，将中文题面排版为带公式的图片，以 QQ「聊天记录」发送。群友用 `/submit <sol>` 分步讲思路、修正方案或请求提示，不需要 @机器人；完整解法评审通过后恭喜解题者，并公布原题号、题名和链接。

**图片模式尚待真实 QQ 协议端联调。** 已有实际使用反馈确认文字出题可以收到题面；新版默认使用 HTML、内置 KaTeX 和 Chromium 生成分页 PNG。独立验证覆盖实际图片、公式与样例保留、分页、发送回退和 AstrBot 图片消息序列化，但不代表真实 QQ 图片发送或模型判断准确率。题面获取支持异步 HTTP 与 Chromium 兜底；2026-10-20 本机实测 `4A`、`2114A` 在 HTTP 返回 403 后，通过浏览器成功获取并缓存。仍取不到完整原文时停止出题，不让模型凭记忆补写。

## 安装与接入

需要 Python 3.12+、AstrBot 4.x（不低于 4.5.7）及一个已经配置好的聊天模型。

1. 在 AstrBot 接入 QQ 的 OneBot v11 协议端，例如 NapCat。AstrBot 负责插件、模型和消息处理，NapCat 负责连接 QQ；「聊天记录」使用这个接口发送。连接步骤参考 [AstrBot 官方 OneBot v11 文档](https://docs.astrbot.app/platform/aiocqhttp.html)。
2. 将插件解压到 AstrBot 安装目录下的 `data/plugins/astrbot_plugin_cf_challenge/`，确认 `main.py`、`metadata.yaml` 和 `_conf_schema.json` 直接位于该目录。使用发布包时去掉多余的目录嵌套。
3. 使用 **AstrBot 所在的 Python 环境** 安装本插件 `requirements.txt`，并安装 Playwright 的 Chromium 浏览器，然后在 AstrBot 插件页面重载插件。依赖处理方式见 [官方开发文档](https://docs.astrbot.app/dev/star/plugin-new.html)。
4. 在插件配置中选择模型；`provider_id` 留空时沿用当前群会话的模型。选择能处理完整题面、擅长算法推理并能按要求输出 JSON 的模型。
5. 配置允许使用的群号；`allowed_groups` 留空表示所有群。默认仅 AstrBot 管理员、QQ 群主和群管理员能出题、改范围、放弃本轮。
6. 设置默认选题范围。若当前部署环境也无法读取 CF 题面，先按后文导入题面，再开启 `local_only`。

在插件目录中，用实际启动 AstrBot 的 Python 执行：

```text
python -m pip install -r requirements.txt
python -m playwright install chromium
```

上面的 `python` 必须属于 AstrBot 环境，不是随便一个系统 Python；Windows 已有虚拟环境时，使用对应的 `.venv\Scripts\python.exe`，不要误用全局 PyPy。Linux 若缺少浏览器系统库，可按 [Playwright 官方说明](https://playwright.dev/python/docs/browsers#install-system-dependencies) 使用 `python -m playwright install --with-deps chromium`，其中系统依赖安装需要相应权限。容器里也要在容器内部安装，运行用户必须能读取浏览器。Linux 还应安装可用的中文字体，例如 Noto Sans CJK。

**默认图片排版也需要 Chromium**，即使开启 `local_only` 或使用已缓存题面。只有关闭 `statement_images` 才跳过排版浏览器；在线获取原题面失败时仍可能使用抓取浏览器。

命令直接发送即可，不需要 @机器人。下面假定 AstrBot 的唤醒前缀包含 `/`；如果修改过前缀，需要在管理面板保留 `/` 才能按本文示例触发，参见 [AstrBot 指令说明](https://docs.astrbot.app/use/command.html)。仅 @机器人 或发送普通聊天文字不会触发本插件的解法评审。

**启用前处理 `/new` 同名冲突**：AstrBot 内置 `/new` 用于新建对话，并有独立权限检查。在 WebUI「插件 → 管理行为 → 指令」勾选「显示系统插件指令」，将**系统插件**的新建对话指令 `new` 重命名为 `chatnew`，保留本插件的 `new`。未处理时可能触发新对话或被系统权限检查拦截；仅提高插件优先级不能绕过前置权限检查。插件不会自动修改系统指令配置。官方行为见 [内置 `/new` 说明](https://docs.astrbot.app/use/command.html#reset-和-new)。

## 群里怎么用

```text
管理员：/cf 范围 1200 1800
机器人：已更新，下次出题生效。

管理员：/new
机器人：[聊天记录：题目描述、输入输出、样例、说明]

群友：/submit 我先讲第一步……
机器人：[只判断已描述的步骤，不提前确认整套方案]

群友：/submit [直接补充后续步骤或修正前面的说法，形成完整正确方案]
机器人：🎉恭喜@XXX 拿下本题 first blood！本题是 CF 722A · Broken Clock (1300) https://codeforces.com/problemset/problem/722/A
```

| 命令 | 作用 |
| --- | --- |
| `/cf 帮助` | 查看用法 |
| `/new` | 从当前范围随机选题；不支持的题面自动换题，最多尝试 3 道；已有活动题时不覆盖 |
| `/cur` | 重发正在进行的题 |
| `/submit <sol>` | 提交思路、补充修正或请求提示／完整讲解；`<sol>` 可包含空格和换行 |
| `/giveup` | 放弃当前群题目并公布原题来源；默认仅管理员可用 |
| `/cf 范围` | 查看本群选题条件 |
| `/cf 范围 1200 1800` | 只修改难度，保留标签和比赛范围 |
| `/cf 范围 {"tags":["dp"],"min_contest":1500,"max_contest":2200}` | 修改指定条件，其余保留 |

默认 `/new`、`/giveup` 和范围修改仅限 AstrBot 管理员、QQ 群主／管理员；`/cur` 和 `/submit` 可由允许群内的普通成员使用。`admin_only_controls` 关闭后，普通成员也可以出题、改范围、放弃本轮。

完整范围示例：

```text
/cf 范围 {"min_rating":1200,"max_rating":1800,"tags":["dp","binary search"],"exclude_tags":["interactive"],"min_contest":1500,"max_contest":2200}
```

难度和比赛编号的上下界都包含在范围内。`tags` 内的标签必须**全部满足**；`exclude_tags` 中任意一个命中就排除。标签使用 CF 的英文标签，例如 `dp`、`graphs`、`binary search`。比赛编号指 CF 网址中的数字，不是标题里的 Round 编号。缺少难度分、非编程题和 Gym 题不参与默认选题。

每群有各自的范围、活动题和出题历史。同一群出过的题不再重复；题池用完后需要扩大范围。修改范围只影响下一轮。默认每人每 30 秒可以提交一次，每次最多 6000 字。**同群、同轮、同一用户的提交会结合前文理解，可以直接补充或修正，不必重发完整方案；最新修正后的说法优先。** 不同用户、群和轮次的对话互不拼接。

同群 `/submit` 按插件接收并处理提交的顺序排队，不再因另一人正在评审而拒绝；等待期间无需重发。前一份未通过或模型调用失败后，自动处理下一份；首个通过者获得 first blood，其余排队者会收到“本轮已结束、这条补充无需再评审”的说明，不再调用模型。这不撤销先前的通过结果。每份排队解答绑定提交时的轮次，不能用于新题。冷却时间仍在轮到该次评审时检查。

## 题面获取、缓存与离线导入

CF 的 `problemset.problems` 接口只提供题目元数据，不提供完整题面，因此插件还要读取题目网页。接口字段见 [CF 官方文档](https://codeforces.com/apiHelp/objects?locale=en)，题库方法见 [官方接口说明](https://codeforces.com/apiHelp/methods?locale=en&mobile=true)。

获取顺序如下：

1. 优先读取已经缓存或人工导入的完整题面。
2. 未启用 `local_only` 且无本地题面时，先用异步 HTTP 读取英文网页。
3. HTTP 返回 403、服务端错误、网络异常，或返回的 200 页面没有题面时，启动临时 Chromium 读取；使用与实际浏览器版本和平台一致的普通 Chrome User-Agent，不登录账号、不保存登录态。
4. **遇到 HTTP 429 限流立即停止**，不切换浏览器继续请求。浏览器仍被拒绝、验证未通过或超时时同样停止，提示重试或本地导入。
5. 只有正文、输入输出、限制和成对样例通过校验，才原子保存到 `statements/<题号>.json`；后续请求和重启后复用缓存。多群共享同一获取锁，避免同时重复启动浏览器。

每次 `/new` 最多随机尝试 **3 道不同的候选题**，不足 3 道时以实际候选数为限。只有明确不支持的图片、SVG、表格或无法恢复的公式格式会触发换题；跳过的题不会翻译、发送或记入已出题历史，也不会永久拉黑，下次 `/new` 仍可能抽到。全部尝试均不支持时停止，提示重新出题、调整范围或导入可完整表达题意的本地题面。网络读取失败、HTTP 429、题面缺字段或样例不完整、翻译失败、发送失败都不会触发换题，沿用各阶段的错误处理。

HTTP 请求超时为 30 秒，浏览器读取总超时为 60 秒，资源清理另有最多 10 秒上限。没有固定的七秒等待。浏览器渲染后的 MathJax 仅使用可对应的原始 TeX，去除重复渲染。提取正文、输入输出和说明前，会把 HTML 明确标出的 `<sub>`／`<sup>` 下标、上标转换成受保护的 LaTeX 公式，支持明确的变量／数字基底、连续上下标、嵌套结构及含上下标的 `.tex-span` 公式；不会把普通标识符 `xi` 猜成 `x_i`。空下标、无明确基底、无法对应的重复上下标、混合且不能可靠转换的公式仍按不支持题面处理，不静默压平成普通文字。样例不参与此转换。获取成功不保证所有题型都可展示；图片、表格等限制见后文。

数据目录由 AstrBot 的 `StarTools.get_data_dir` 决定，通常是 AstrBot 工作目录下的：

```text
data/plugin_data/astrbot_plugin_cf_challenge/
  problemset.json          # 题库缓存，正常情况下每小时更新
  challenges.sqlite3       # 本群范围、轮次、出题记录、参考分析与提交时间
  statements/
    4A.json                # 自动缓存或人工导入的完整题面
```

可以在浏览器正常访问原题后保存完整 HTML，再在本插件根目录执行以下命令。`--data-dir` 必须改成**实际运行的 AstrBot** 的插件数据目录，容器部署时注意挂载位置。

```text
python -m tools.import_statement --problem 4A --source saved-problem.html --data-dir /path/to/AstrBot/data/plugin_data/astrbot_plugin_cf_challenge
```

导入工具会检查正文、输入输出、限制和成对样例。已有同名文件时默认拒绝覆盖；明确需要替换时加 `--overwrite`。

旧缓存若已经将下标压成 `xi` 等普通文本，无法仅凭该文本可靠恢复；升级不会自动改写已有缓存或轮次。可从完整原网页重新保存 HTML，再用上述导入命令加 `--overwrite` 覆盖对应缓存，供后续读取使用。已有活动轮次保存着当时的原文和译文，不会因覆盖缓存而自动重译，`/cur` 也只重发当前题面。

也可以把完整原文整理成 UTF-8 JSON，然后用相同命令导入。以下仅说明字段格式，是自行编写的例子，**不对应某道 CF 原题**：

```json
{
  "body": "Given two integers a and b, calculate a+b.",
  "input_spec": "Two integers a and b, each between 1 and 100.",
  "output_spec": "Print their sum.",
  "samples": [["2 3", "5"]],
  "time_limit": "1 second",
  "memory_limit": "256 megabytes",
  "note": ""
}
```

导入后在插件配置中打开 `local_only` 并重载插件。这样只从「同时符合范围、且已缓存或导入完整题面」的题中抽取；不会随机抽到另一道尚无本地题面的题。题库第一次仍需网络读取，之后可以使用已缓存的题库。

## 中文题面与解法评审

出题仍使用两次模型调用：翻译和校对。翻译前，程序把正文、输入输出和说明中的公式替换为唯一占位符，原始 TeX（包括由 HTML 上下标转换出的公式）保留在程序内，不要求模型重新生成公式。模型只翻译周围文字并原样保留占位符；程序逐字段检查占位符是否缺失、重复、损坏或跨字段移动，并拒绝模型自行新增的公式，验证后再逐字回填原公式。同一字段内允许调整公式提及的语序，是否忠实于原意仍由后续校对检查。

校对模型收到的是完整原文和已回填真实公式的中文，不是占位符；它核对条件、变量、上下标、括号层级和说明，并生成内部参考分析。占位符损坏时停止发布，不靠放宽校验、额外重试或换题绕过。程序生成的占位符只用于本次翻译，不写入题面缓存或最终消息，并避开原文中已有的同形文本；样例不参与替换，仍由程序直接附上。校对不是对原网页或最终图片的视觉检查，因此抓取阶段的结构保留仍是必要条件。题面不显示题名、题号、链接、难度和算法标签。

### 图片题面

- `statement_images` 默认开启：正文按纯文本与公式组成安全 HTML，不解析通用 Markdown；整页由 HTML/CSS 排版，支持 `$$$...$$$`、`$...$`、`$$...$$`、`\(...\)`、`\[...\]` 公式，再用 Chromium 截图。下标、分数、根式等由 KaTeX 排版；不会自行修正模型已经写错或丢失的数学符号。
- 图片顶部仅保留时间限制、内存限制，不显示“算法挑战 #轮次编号”、提交说明或评审结果提示；文字题面同样不附带提交说明和评审结果提示，但保留轮次标题。
- 图像宽度为 1440 像素，长题面按实际文字行和公式位置分页；不按固定字符数截断，也不截掉尾页内容。样例采用等宽字体、保留空格换行，不解析其中的公式或 HTML。
- 开启 `merged_forward` 时，每张图片作为聊天记录中的一条节点，通过 AstrBot 的 `Image.fromBytes` 发送，NapCat 不需要访问插件本地文件路径。关闭它则逐张发图片。
- 图片全部生成后才开始发送；合并转发失败会提示并改为直接逐张发图片。直接图片发送失败会使本轮保持发送失败状态，不接受解法。
- 图片渲染失败时会明确提示，并回退到完整文字题面。将 `statement_images` 关闭，可持续使用原文字模式；修复后重新开启，再用 `/cur` 重发当前题，不需要重新抽题、翻译或调用模型。
- KaTeX **0.19.0** 的脚本、样式及 20 个 WOFF2 字体随插件内置，字体嵌入 CSS，渲染时禁用外部请求，不依赖 CDN。第三方 MIT 许可见 `cf_challenge/assets/katex/LICENSE`。题面内容经过 HTML 转义，样例不会执行脚本；外部 TeX 功能及不支持的公式会触发文字回退，而不是生成错误公式图片。

修改 `statement_images` 或 `merged_forward` 后保存配置并重载插件。更新插件代码不需要删除插件数据目录，已有活动题可继续使用。

如果题面仍以普通图片出现，先确认实际部署版本已重载、`merged_forward` 已开启，且机器人通过 OneBot v11 接入（插件识别的平台名为 `aiocqhttp`）。关闭合并转发或使用其他平台时，代码会跳过聊天记录发送；收到“题面图片合并转发失败，将改为逐张发送”则表示已尝试转发但调用报错。需要结合该次 AstrBot 和 NapCat 日志定位，不能仅凭普通图片判断原因；分享日志时请隐藏 token、密钥、账号和无关消息。独立序列化与接口路由验证不能代替实际群收发验证。

### 文字解法评审

checker 先按时间顺序整理同一用户当前有效的方案，最新修正覆盖旧说法，未撤回的步骤继续保留，不要求重发整套方案。历史助手反馈只用于理解对话指代，可能判断错误，不是事实或必须完成的补充清单；也不能把助手讲出的解法当作用户已经提交，除非用户明确采纳或解释过。按口述实际意思理解，接受口语、缩写和明显转写错字；临时变量与题面字母重名时先结合上下文统一含义，仍有影响结论的歧义才问一个必要问题。只确认已讲的部分，不把未讲步骤当作遗漏或提前通过。

错误反馈先说“思路有问题”或“思路对，实现这里有问题”，用一至三句话指出当前最关键错误及原因，必要时给最小反例；不主动提供修法、完整解法或代码。默认用简体中文，结论先行，术语和公式配白话说明，不复述题面，不用“显然”等词替代推导。对明确算法可直接推导的复杂度、简单边界和正确性理由，由模型自行核查；不能替用户发明关键算法或补造非平凡论证。

核查范围以题目要求输出的内容为准：只求最优值、长度或存在性时，检查可实现性及必要下界，不额外强求两个固定常数、完整数组或代码；题目要求构造时才进一步要求相应构造方法。对用户已经给出的关系式与选择条件，可以自行核验简单恒等式、可逆运算、能否避开有限禁值及标准前缀规律，但仍须检查取值范围、非负性、互异性等实际约束，不能无条件认定总能构造。已有实现描述或代码仍照常检查；概念上考虑一段元素不等于实现时逐个遍历，只有真正影响复杂度且无法确定的实现差异才需要澄清。

追问前先检查用户后续说法是否已经解决旧问题；用户没有按助手预设的措辞回答，不等于没有回答。确有缺口时只指出当前最关键、无法核验的一点，并提出一个能直接回答的问题，不把多个补充要求串成一问。通过前的独立复核沿用同样标准，不继承旧助手的结论，也不以凑出新的缺项为目标。

`/submit 不会`、`/submit 想不出来`、`/submit 不知道怎么改`、`/submit 给点提示` 会请求逐步引导：保留已有正确部分，每轮围绕一个卡点给一个小提示、小例子或具体问题，仍不会再拆小；原思路走不通时简短说明卡点，从有效观察引出新方向，没有已有思路时从简单例子开始。明确请求完整讲解或代码时才提供完整内容。**提示和完整讲解都不会判定用户通过或揭晓来源。**

群友解法有三种结果：

- **通过**（`accepted`）：用户已给出完整方案，步骤、关键理由、边界和复杂度得到支持；还要另一次独立复核同意，才结算并揭晓。群内发送一条 first blood 通知，真正 @解题者，并列出题号、题名、难度和链接，不附带评审理由。
- **有错误**（`incorrect`）：有有效反例或明确的错误推导，按上述简短格式反馈，不揭晓题号。
- **需要补充**（`needs_more`）：尚不能可靠判断或复核意见不同，不结算；部分步骤确认、逐步提示和完整讲解也使用此内部状态，公开反馈不会统一加上催补标题。未讲到的内容不被当作遗漏。

内部参考分析由模型推导，**不是 CF 官方题解**；判断也不能只看提交是否与参考分析相似。不同的正确解法允许通过。两次复核仍然使用所选模型，不能保证消除误判；这里没有运行代码，也没有通过 CF 的正式测试。模型输出格式损坏、缺失必需字段或调用失败时不会算通过。

模型调用使用专门的题面、当前提交及该用户本轮的提交和公开反馈，不带日常聊天记录，不授予工具，也不执行群友提交的代码，不能声称已运行验证。活动轮次的对话保存在插件数据库，重载后保留；模型调用失败或取消时保留用户本次说法，不伪造回复。通过或管理员揭晓时清空本轮所有用户的对话，新轮从空上下文开始；旧数据缺少对话字段时按空记录读取，无需清库。对话历史不保存内部评审依据或参考分析；非通过反馈继续屏蔽原题名、题号和链接，但不能保证识别模型产生的所有间接暗示。

## 已处理的异常与当前限制

- 同群解答排队评审；正在出题或评审时，出题、放弃本轮和修改范围等控制操作仍可能收到忙碌提示。不同群互不占用这把锁。
- 排队仅保存在当前插件实例的内存中，取消的等待任务会退出队列，评审任务失败或取消后不会阻塞后续提交。插件重载或进程重启后，等待中的解答不会自动恢复，需要重新提交；已有活动轮次仍按数据库记录恢复。不支持多个进程共享数据库时的排队协调。
- 题面成功发送后才成为活动题；发送失败或重启前未确认送达的轮次不会继续接受解法。网络超时有时意味着 QQ 已收到了消息，因此回退发送或重试可能产生重复的题面消息。
- 图片聊天记录发送失败时改为直接发图片；文字模式的合并转发失败时改发分段文字。原文解析支持原始 TeX、可恢复的 MathJax 及可明确转换的 HTML 上下标；含图片、SVG、表格、孤立 MathML 或无法可靠恢复的公式结构的原题不会发布，出题时按上文规则有限次换题，避免漏掉信息。
- `allowed_groups`、默认范围和模型选择等插件面板配置修改后需要重载插件；群内 `/cf 范围` 立即保存。
- 已判定解决后，结果发送仍可能因 QQ 网络故障丢失。当前没有结果补发命令，需要从数据目录查看记录。
- 首版由管理员按命令出题，不包含定时推送、积分榜、代码评测或已做题账号同步。

## 开发与验证

下面是在 Windows PowerShell、源代码目录中的命令：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
.venv\Scripts\python.exe -m tools.build_plugin
```

Linux 中把 `.venv\Scripts\python.exe` 换成 `.venv/bin/python`。自动测试中的模型、QQ 事件和转发通道均为模拟对象；它们验证流程和消息结构，不验证真实模型的数学判断。图片功能另外使用实际 Chromium 验证排版、分页、离线资源和异常路径。发布包包含运行文件及公式资源，不包含测试、虚拟环境、数据库、截图预览或密钥。

建议使用 Git 管理源码、测试、配置定义和文档。`.gitignore` 已排除虚拟环境、运行数据、数据库、安装包、环境变量文件、实际 `config.yaml` / `config.json`、密钥、日志和浏览器认证状态目录；不要把 AstrBot 运行配置或账号凭据提交到仓库。初始化、首次提交和远程推送是不同操作，提交前应检查暂存文件范围。

接入后的验收顺序：管理员设置范围并出题 → 确认聊天记录的题面完整且未显示来源 → 群友分步讲解、修正错误、请求提示／完整讲解，确认均不提前结算 → 同用户补充完整方案后检查独立复核与揭晓 → 换用户、换群、换轮和重载检查上下文隔离与恢复。实际发送消息和调用模型应在你准备好连接后进行。
